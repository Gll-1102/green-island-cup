# 绿岛杯足球赛事管理系统 Green Island Cup

> 一套面向高校真实赛事、全栈自研并已上线运营的足球比赛管理平台。从报名、抽签、赛程、检录、实时比分到裁判评分与数据统计，覆盖一场校园足球赛事的完整生命周期。

## 项目背景与成果

本系统为校内足球赛事的实际办赛需求而设计，并非练手 Demo，已在真实比赛中投入使用：

- **真实上线**：部署于云服务器（Ubuntu 22.04 + Node.js + PM2），公网可访问，支持比赛日多人同时在线。
- **真实用户与数据**：服务 **11 支球队、28 场比赛（男子 18 场 / 女子 10 场）**，贯穿报名、检录、比赛与评分全流程。
- **独立完成**：从需求分析、数据库设计、前后端开发、部署运维到现场技术保障，由个人独立主导，核心代码自研约 **1.34 万行**。
- **持续迭代**：历经 **62 个版本**演进，数据库共 **31 张表**，在真实使用中不断修复问题、优化性能。

## 核心功能

**四级角色权限体系**：管理员 / 裁判员 / 球队（队长）/ 游客，不同角色看到的功能与数据严格隔离。

- **赛事管理**：球队与球员报名、资格审核、抽签分组、自动赛程编排、积分榜与射手榜。
- **比赛日流程**：球员检录、阵容签到、换人登记、实时比分与事件记录，数据通过 WebSocket 实时推送。
- **裁判端**：裁判账号自动生成、裁判评分、比赛报告提交。
- **运营保障**：公告通知（分全员/球队/裁判可见范围）、停服维护窗口、操作日志、系统自检。
- **数据安全**：游客浏览公开信息时自动隐藏学号、手机号等敏感字段。

## 技术栈

| 层 | 技术 |
|---|---|
| 后端 | Node.js（内置 `node:sqlite`）、Express 4 |
| 实时通信 | Socket.IO 4（已做 Origin/Host 同源校验） |
| 数据库 | SQLite（WAL 模式，31 张表，全参数化查询） |
| 前端 | 原生 HTML / CSS / JavaScript（无重型框架依赖） |
| 安全 | bcryptjs 密码哈希、express-session、图形验证码、输入消毒、安全响应头 |
| 工具与部署 | PM2、Multer 上传、ExcelJS、Puppeteer、QRCode、compression |

## 快速开始

**环境要求**：Node.js 22 及以上（项目依赖内置的 `node:sqlite` 模块）。

```bash
# 1. 安装依赖
npm install

# 2. 配置环境变量（按需修改）
cp .env.example .env

# 3. 启动（首次启动自动建库并写入种子数据）
npm start
```

启动后访问 `http://localhost:3000`。初始管理员账号与密码通过环境变量 `ADMIN_INIT_PASSWORD` 配置，未配置时使用占位值，**请在首次登录后立即修改**。

## 安全设计

- **密码安全**：所有密码使用 bcrypt 哈希存储，球队密码随机生成、首次登录强制修改；连续输错 5 次自动锁定。
- **密钥管理**：会话密钥优先读取环境变量 `SESSION_SECRET`，未配置时在本地生成随机文件；密码、密钥等敏感配置均不写入代码仓库。
- **访问控制**：登录需图形验证码，接口级鉴权；SQL 全部参数化，动态表名走白名单，全局输入消毒防止 XSS。
- **传输安全**：生产环境建议配置域名 + HTTPS（预留 `ssl/` 目录，不打入部署包）。

## 性能优化亮点

针对比赛日"打开卡顿、点击无反应"的真实问题进行过专项优化：

- 定位到根因是全局 `no-store` 导致所有静态资源无法缓存，叠加小带宽导致资源加载阻塞。
- 修复缓存策略（JS/CSS/图片 7 天缓存 + ETag）、压缩图片、静态资源走本地缓存。
- **效果：重复访问整页额外传输量从约 210KB 降至约 4.6KB**，显著改善弱网环境下的使用体验。

## 工程化与运维

- **PM2 守护**：异常自动重启、内存阈值保护、日志切割、开机自启。
- **自动备份**：数据库定时备份并保留最近 10 份，备份前做 WAL checkpoint 保证可恢复。
- **离线自检**：内置自检脚本，可接入定时任务，快速发现运行异常。
